## 預測是拿來做什麼的

在衛生單位裡，預測是一種**規劃工具**，不是預言。它把「登革熱很多」變成「十月初每週大約準備 20 到 60 例，之後逐漸下降」，這樣醫院才能開床位，市政府才能排 4S 和噴藥小組，藥局才能訂購快篩試劑。一個好的預測會附上**三樣東西**：一個數字、一個範圍，以及一份過去的表現紀錄。

## 先做基準線

**基準線**（baseline）是一位疲憊的疾病監測專員（DSO）在紙上就能做出的最簡單預測。任何模型都必須贏過它，否則就不值得費這番功夫。

- **最後觀測值：** 下週 = 這週，重複下去。
- **季節性天真預測（seasonal naive）：** 接下來幾週 = 去年的同一週。

為了公平評分，我們使用**滾動起點回測（rolling-origin backtest）**：假裝我們站在過去的某一週（這就是**起點**），只用當時已知的資料預測接下來 8 週，事後才拿來和實際發生的結果比較。我們從 2023-W01 到 2026-W31，每隔一週做一次：共 **94 次預測**。分數是**平均絕對誤差**（mean absolute error, MAE）：平均每次差多少，單位是每週病例數。

:::{admonition} 問問 Tala
:class: ph-ask-tala
我有一個 NumPy 陣列 `y`，是按時間順序排列的每週登革熱病例數（虛構範例：`[5, 9, 11, 4, ...]`，長度超過 52 週）。對於在第 `o` 列所做的預測（只知道 `y[:o]`），我想用兩種基準線預測接下來的 `H = 8` 週：「最後觀測值」（重複 `y[o-1]`）與「季節性天真預測」（複製 `y[o-52 : o-52+8]`）。請對一串起點都做一遍，並給我對照真實值的 MAE。再加一個我可以手算驗證的檢查。
:::

:::{admonition} Tala 說
:class: ph-tala-says
```python
H = 8                                             # 預測期間：8 週
first, last = row_of["2023-W01"], row_of["2026-W39"] + 1

```
:::

:class: ph-check

2. 每一段歷史都必須停在它的起點：`len(context) == o`。如果預測看得到它要預測的那幾週，分數就毫無意義。

## 零樣本基礎模型：TimesFM 3.0

**TimesFM** 是 Google 的**時間序列基礎模型（time-series foundation model）**。它只訓練過一次，用的是規模非常龐大的時間序列集合。我們以**零樣本**（zero-shot）的方式使用它：不用我們的資料再訓練，只要說「這是歷史資料，請給我接下來 8 週」。它會回傳中位數預測與九個**分位數**；0.1 與 0.9 分位數圍出一個 **80% 預測區間**，也就是真實值大約每 10 次有 8 次會落在這個範圍裡。

筆記本展示了真正的呼叫方式，在 Google Colab 執行 `pip install "timesfm[torch]"` 之後就能跑（模型權重約 1.3 GB，只需下載一次）：

```python
from timesfm3 import ModelConfig, TimesFM3Evaluator

config = ModelConfig(
    checkpoint_path="google/timesfm-3.0-pytorch",  # Hugging Face 上的權重（約 1.3 GB，只在第一次執行時下載）
    per_core_batch_size=32,                        # 每次前向運算處理的序列數
    device=tsfm.default_device(),                  # GPU 執行環境用 "cuda"，否則用 "cpu"
)
model = TimesFM3Evaluator(config)
```

```python
contexts = tsfm.rolling_origin_contexts(y, origins)
bt = tsfm.forecast_batch(model, contexts, H, cache_key="backtest_cases", cache_file=CACHE)
```

載入模型時，`tsfm.forecast_batch`（來自本書的 `epi_learning` 套件）會呼叫 `model.predict_batch(...)`。建置這個網站時並不會下載模型；輔助函式會重播同一份筆記本先前用真正的 TimesFM 3.0 跑出並儲存的預測，而且每個儲存格都會印出它走的是哪一條路徑。

## 計分板

| 期間 | 最後觀測值 | 季節性天真預測 | TimesFM 3.0 | 80% 區間涵蓋率 |
|---|---:|---:|---:|---:|
| 平常年份 2023–2025（75 次預測） | 4.76 | 4.31 | **3.50** | 79% |
| 2026 年，颱風年（19 次預測） | 6.22 | **5.21** | 5.32 | 72% |

*MAE，單位為每週病例數，取未來 8 週的平均。*

在平常的年份，TimesFM 明顯最好，而且它的 80% 區間很誠實。到了 2026 年，它**並沒有比照抄去年更好**。它預測下一週最準（MAE 1.97），但到第 8 週就落後了（10.08，季節性天真預測是 8.68）。只看一個整體平均會把這件事藏起來。**一定要把異常時期單獨拿出來評分。**

:::{admonition} Tala 搞錯了
:class: ph-oops
Maya 要求「更好的基準線：所有年份同一週的平均」。Tala 的版本在全部 94 次預測上的 MAE 是 **3.27**，比同樣這批預測上 TimesFM 的 3.86 還好。Doc Mon 只問了一個問題：
*「這個平均用了哪幾年？」* 全部——**包括被預測的那幾週本身**。這就是**資料洩漏（leakage）**：預測偷看了答案。如果只平均每個起點*之前*的三年，結果是 **3.95**，比 TimesFM 的 3.86 略差。

另一個比較隱微的手法，是只報告**最好**的那一週。TimesFM 最好的起點 MAE 是 0.54；最差的（2026-W31）是 31.50。誠實的數字是全部平均：3.86。

怎麼抓出這兩種問題：問自己「*這個預測在那一天真的做得出來嗎？*」，並且報告所有起點的平均，再加上最差的那一個。
:::

## 疫情起飛的時候

最重要的就是曲線轉彎的那幾週。給定到 2026-W31 為止的歷史，TimesFM 預測每週約 **10 例**。接下來四週實際是 **33、28、48 和 34**。之後的八週，沒有任何一週落在它的 80% 區間裡。從 W32 起，區間只涵蓋了 29% 的週數；直到 W34，暴增已經進到歷史資料裡，才全部涵蓋。

模型沒有壞。它只知道登革熱曲線*通常*接下來會怎麼走，卻不可能知道三週前一個颱風淹了這座城市。

**加入雨量有幫助嗎？** 在這份合成序列裡，雨量領先病例約 7 週，而 TimesFM 3.0 接受雨量作為**共變數（covariate）**。加入雨量之後，回測的 MAE 幾乎沒變（2023–2025 年 3.50 → 3.47，2026 年 5.32 → 5.27），而且從 W31 起預測仍停在每週約 9–12 例，儘管 Amihan 帶來的雨——序列中最濕的一週——早已在歷史資料裡。共變數有沒有用，要在同樣的回測裡證明。

## 十月與十一月的預測

用到 2026-W39 為止的全部資料，TimesFM 的中位數從 **W40 的 42 例**（80% 區間 24–63）下降到 **W47 的 16 例（6–44）**。八週的每週中位數加起來共 215 例；2025 年同樣的八週則是 75 例。

:::{admonition} 檢查一下
:class: ph-check
1. **最後一週完整嗎？** 不完整：W39（45 例）還在陸續通報中（見[第 06 章](06_signals_and_thresholds.md)）。用到 W38 為止的資料，模型預期 W39 有 53 例。把 W39 排除，W40 的預測會從 42 升到 46。當最新一週會左右預測時，要講出來。
2. **區間寬嗎？** 很寬，而且就該如此：W47 的 6 到 44 例是一句誠實的「我們不知道確切是多少」。
3. **和基準線比較。** 季節性天真預測說 8 週共 75 例。那是一個正常秋天的樣子，不是這個秋天。
:::

Maya 給委員會寫的話是：*「十月初每週大約準備 20 到 60 例登革熱，十一月可能逐漸下降。我們每週都會更新；若出現新的颱風或重症病例增加，預測就會改變。」*
